# Scoring rules

- The model marks facts; `scorer.py` decides what a fact costs. Never move a scoring decision, cap or threshold into a prompt. A prompt may explain a rule, not hold it.
- A blocking fact (sponsorship refused, a required language the profile lacks AND the read quotes from the ad (otherwise a language-unconfirmed flag), a place outside `allowedLocations`; `blocking.py`) sets the verdict to Blocked via `labels.verdict`, never the number; `blockedFrom` keeps the unblocked verdict.
- Caps live in `scorer.py` (unrelated title 40, off-track 50, red flag 54, no profile stack 50, onsite or hybrid outside the relocation scope 54) and `ceilings.py` (scoringVersion 1.6: role class other 54, applied by `role_class.stamp`; engine-status ceiling 69 at theta 0.3, applied by `run_scoring` only for ads with engine answers; "not available" never lowers). A security clearance or US-status requirement is a blocker (`blocking.clearance_state`) only when the sentence says the ad REQUIRES it (`blocking.DEMAND`: required, must, requiring, ability to, strictly, ...); a bare mention ("Security clearance.") or a benefits line is `clearanceUnconfirmed`, a flag beside the score, never Blocked. The Skill-dimension role-title change failed the guard: off (`ceilings.SHIPPED_FIXES`). They lower a score; nothing is ever hidden. Work authorization, the language gap and the location state are **not** caps since scoringVersion 1.5: they are states beside the score (`eligibility.py`, `languageGap`, `workAuthorization.location`) and no code reads them back into `matchScore`. An empty or unreadable description is `not_read` (no Fit Score); `insufficient_evidence` (readable, nothing extracted) is a status only (`data_sufficiency.py`). Facts of an unknown shape count as no facts (`facts_guard.py`). `SCORING_VERSION` in `scorer.py` is stamped on every row.
- An ad without a current engine answer (new or changed ad, changed profile / prompt / requirement set, engine off, failed call, confirmed cheap-gate fail) carries `engineCoverage` `not_evaluated` and the reason "Ceiling not evaluated: ..." (`ceilings.stamp_engine_coverage`, shown under Limits on Job Details); it passes the engine ceiling only because nothing was evaluated, and the row says so. `python/job_scoring/engine_missing.py` estimates and fills the fillable ones (owner-run, `--max-usd`, `--confirm`); nothing auto-runs it.
- **Experiment B exception (owner brief 2026-11-19; narrowly scoped):** the rule "never move a scoring decision into a prompt" is suspended ONLY for the evaluation code in `python/calibration/fit_b.py`, `fit_b_metrics.py` and `scripts/measure_fit_b.py` (one AI call per ad returns a 0-100 professional-fit number, pre-registered in `~/holojob-eval/exp-b-plan.md`). It runs through the AI gate with its own feature (`fit-b-experiment`), owner-run with `--confirm` and `--max-usd`, writes only under a scratch dir, never to `scored_jobs.json`, and nothing in `python/job_scoring` or the pipeline imports it. The production path keeps the rule unchanged; a B win would not change production without a new owner decision.
- **Jobs list tiers (owner decision 2026-11-21, option A; frontend `src/modules/jobs/fitTier.js`):** the list shows three coarse tiers derived from scoring 1.6 output (Strong fit 70+, Possible fit 55-69, Weak fit below 55 or a Skip verdict; blocked ads in no tier) and makes no claim about the order inside a tier: no sort or tie-break by the numeric score, the score stays in the detail view. Inside a tier the order is remote-feasible first, newest, jobId. Do not add a within-tier ordering without a pre-registered win (experiment B did not win; `docs/DECISIONS.md`).
- Title tiers (`role_tier.py`, vocabulary in `src/data/roleFamilies.json` `titleRules`): target, near, unrelated. Only unrelated is capped, and it sets `hardCapped` and a reason. No family or no vocabulary means no cap. Serbian title wording (Latin folded, Cyrillic) lives in the same JSON; a Serbian project / delivery manager title goes to `productResponsibilityTitlePatterns`, like the English one.
- `searchRoleVariants` may hold fragments ("Senior Product"): `role_match` ignores a variant that only opens a longer target role. Do not remove role names from the keyword bank without recalibrating `TARGET_COVERAGE`.
- Enrichment (`enrich_jobs.py`) never sees the candidate and never scores. Facts cache on the job under `llmFacts`, keyed by `job_fingerprint.py` (the only definition).
- The fit judge (`llm_enhancer.py`) returns a category, never a number; code applies +5 / 0 / -8 / -15. Only jobs scoring 65+ are sent, at most 50 per run. `--judge` is the only way it runs; `/api/scoring/run`, Re-score and Run Full Pipeline never judge.
- A dealbreaker needs the candidate text to contradict a condition. Silence goes under `missing`.
- Changing `_candidate_digest` changes what leaves the server: do it deliberately and update the field list in `CLAUDE.md`.
- Salary (`salary.py`) and the apply-by date (`deadline.py`) are display metadata; they never reach `matchScore`, label, priority or red flags, and an expired date does not close an ad.
- After any weight or dimension change, recheck `P1_MIN_SCORE` in `labels.py` against a run.
- Text compares through `text_utils.py` (diacritics folded: "Niš" = "Nis").
- Unknown never caps: a place `geography.py` does not know is unknown.

Why each dimension looks the way it does, the caps, and the open problems: `docs/ARCHITECTURE.md`.
